# Achievements

[简体中文](achievements.md) · English

Waifu v1.0 has an achievement button between the theme and share buttons. The window contains 42 achievements: 27 with bronze, silver and gold levels, and 15 one-time achievements. Names, conditions and flavor text support English and Chinese, with 96 badge images.

See the [bilingual achievement catalog](achievement-catalog.md) for every achievement's Chinese and English name, tier thresholds, unlock condition and flavor text.

## Counting and viewing

Counting starts when a supported production Waifu version first starts; opening the achievement window is not required. Earlier usage remains available on the dashboard but does not earn achievements retroactively. The achievement profile keeps its own calendar time zone, so later system time-zone changes do not rewrite its start time or earned dates.

Recent shows the six most recent achievements. Completed achievements appear first, followed by earned bronze or silver levels, then locked achievements. Search and status filters narrow the list. Click a material swatch to preview another badge level; hover an earned swatch to see its date. Previews do not change progress or award achievements.

Locked tiered achievements show bronze by default. Unearned gold, silver, bronze and stone badges are dimmed while retaining their material colors. Previewing an unearned level keeps it dimmed; earned levels display normally.

New awards or upgrades show “New achievement” on the right of the refresh panel. Clicking it opens Recent. The notification is acknowledged only after that version is displayed successfully. Awards arriving while you view the window remain unread. Ordinary progress changes do not trigger a notification. Read state is shared between pages and survives restart.

Share achievements count successful copy or save actions, character achievements count characters actually applied, and restore achievements count completed, verified restores. Opening a window or previewing a badge does not count as one of these actions.

## Profile, backup and recovery

The default profile is `~/.codex-usage/achievements.sqlite`. A custom usage database has its achievement file beside it, with a name generated by the application. This independent file keeps the counting start, earned dates, operation records and read state. Do not delete it as a cache. Rebuilding derived caches preserves it.

Waifu history backups include an achievement sidecar and its manifest entry when a profile exists. A new Lite backup from an active usage database neither looks for nor reads an adjacent achievement profile and does not include that active profile. Keep the complete backup directory or bundle, rather than only its main SQLite file. Keep source logs, import configuration and external cold-history files as described in the [upgrade guide](15-delivery-upgrade.en.md).

Old v1 usage packages still require a price snapshot; v2 retains its meaning as the format with an achievement attachment, while v3 supports usage packages without prices. Lite can validate declared achievement attachments read-only and transfer them unchanged without activating a profile. Imported instances do not start achievements either. See [history retention](history-retention.en.md) for format and transfer rules.

An ordinary history restore does not restore the backup's achievement profile. A full restore is available only in Waifu and must be explicit. Use the Waifu runtime package or the default source entry:

```sh
node src/cli.js history restore <packageDB-or-bundle> <new-database-or-directory> --with-achievements --home-dir <profile-home>
```

It preserves the backup's profile identity, start time, calendar, level dates, read state and evidence. It does not merge over another profile or switch a running service. Old v1 usage packages remain readable through ordinary restore. Older achievement profiles migrate transactionally; a failed migration preserves the old version for retry.

If preparation was interrupted before the final manifest was published, preserve the source and use a new target. If the target was fully published but recording completion was interrupted, repeat the same command: the application verifies the target and replays its completion receipt without overwriting it or awarding twice.

## Switching editions

Waifu provides all 42 achievements and 96 badges. Lite preserves an existing profile without opening, migrating, advancing or deleting it. Imported instances do not start achievements either.

Returning to Waifu preserves the profile identity, counting start, fixed time zone, earned dates and read state. It catches up on facts that remain provable without inventing share or character actions during Lite use. See [getting started](01-getting-started.en.md) for edition choices and startup commands.
