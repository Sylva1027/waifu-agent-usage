# 成就

简体中文 · [English](achievements.en.md)

Waifu v1.0 在顶部深浅色按钮与分享按钮之间提供成就入口。窗口包含42项成就、27项铜银金分级成就和15项单次成就，使用96张徽章。名称、条件和解说均支持中英文。

全部成就的中英文名称、等级门槛、解锁条件和解说见[成就条件与解说中英对照](achievement-catalog.md)。

## 计数与查看

首次启用成就或从旧版升级时，Waifu 会在用量同步后自动评估已有历史，发放已达标的徽章，并带入未达标的进度。之后同步的用量也会继续计入。成就档案保存自己的日历时区，已有徽章保留原获得日期。

“近期获得”展示最近六项，列表中满级或已获单次成就优先，然后是已获铜银级，最后是未获得。搜索和状态筛选可以进一步缩小列表。右侧铜银金材质图例可以切换预览，悬停已获得的图例可查看日期；预览不会授奖或改变进度。

未获得的分级成就默认显示铜牌；金、银、铜和石头徽章统一变暗，同时保留材质本色。切换预览时，未获得的等级仍变暗，已经获得的等级正常显示。

新获得或升级时，自动刷新框右端显示“新成就”。点击后进入“近期获得”，成功显示才将当时看到的版本标为已读。查看期间新增的成就继续保留提示；普通进度变化不触发提示。其他页面同步已读，重启程序也保留未读状态。

分享成就记录实际成功的复制／保存，角色成就记录实际应用的角色，恢复成就记录已完成并验证的恢复。仅打开窗口或切换徽章预览不会获得这些成就。

「我全都要！」以八位现役角色为准。旧档案升级时按已用过的现役角色重新结算，已获得的徽章保留原日期和已读状态。

## 档案与备份

默认档案位于 `~/.codex-usage/achievements.sqlite`。自定义用量数据库时，成就档案是其旁边的独立文件；准确位置由程序的数据库配置决定。它保存档案启用时间、获得日期、操作记录和已读状态，不能当作可重建缓存删除。派生缓存重建会保留这些记录。

Waifu 的历史备份会在存在成就档案时一并保存独立成就文件及清单摘要。Lite 从活动用量库创建的新备份不查找或读取旁边的成就档案，也不附带该活动档案。保留整个备份目录或完整 bundle，不能只留下主 SQLite 文件；原始会话日志、导入配置和其他外部冷历史仍按[升级说明](15-delivery-upgrade.md)保留。

旧 v1 用量包仍要求价目快照，v2 继续表示带成就附件的格式，v3 支持不携带价目的用量包。Lite 可以只读校验并原样转移旧包声明的成就附件，不将它激活为活动档案；导入实例也不启动成就。格式与转移规则见[历史保留](history-retention.md)。

普通历史恢复不恢复包中的成就档案。完整恢复仅由 Waifu 提供，需要显式指定；以下使用 Waifu 运行包或默认源码入口：

```sh
node src/cli.js history restore <packageDB或bundle目录> <新的目标库或目录> --with-achievements --home-dir <对应home>
```

完整恢复保留备份中的档案身份、启用时间、固定日历、等级日期、已读状态和证据；不会合并覆盖另一份已有档案，也不会自动切换正在运行的程序。旧 v1 用量包仍支持普通恢复，恢复的用量可在启动 Waifu 后参与成就评估。已有旧版成就档案会自动进行事务迁移，失败保留旧版本以便重试。

恢复准备被中断或最终清单尚未发布时，保留源资料并改用新目标。目标已完整发布、仅成就记账被中断时，可重复同一条命令，让程序校验目标后补记完成凭据；不会覆盖目标或重复授奖。

## 版本切换

Waifu 提供 42 项成就、96 张徽章。Lite 保留已有成就档案，不打开、迁移、推进或删除它；导入实例也不启动成就。

切回 Waifu 后沿用原档案身份、启用时间、固定时区、获得日期与已读状态，并补算仍可核实的用量。分享和角色成就以档案中已记录的操作为准。版本选择与启动见[开始使用](01-getting-started.md)。
