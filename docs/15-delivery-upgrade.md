# 升级与回滚

简体中文 · [English](15-delivery-upgrade.en.md)

v1.0b 提供 **Waifu Usage**（完整版）与 **Agent Usage**（轻量版），包内 `version` 为 `1.0.2`。两版沿用既有用量数据目录和来源配置。

从 v1.0a 换用这一版时，先停掉当前实例，再用同一版别的新 ZIP 替换程序文件，然后按原参数启动。

- [下载 1.0b-waifu.zip](https://github.com/Sylva1027/waifu-usage/releases/download/v1.0b/1.0b-waifu.zip)
- [下载 1.0b-lite.zip](https://github.com/Sylva1027/waifu-usage/releases/download/v1.0b/1.0b-lite.zip)
- [v1.0b Release](https://github.com/Sylva1027/waifu-usage/releases/tag/v1.0b)

运行要求为 Node.js `>=23.8`。两份 ZIP 均可直接运行，无需安装 npm 依赖或编译。首次安装和验收平台见[开始使用](01-getting-started.md)。

## 保留数据升级

1. **解压新包到新程序目录。** 暂时保留旧程序，避免覆盖正在使用的文件。
2. **停止旧实例。** 前台在原终端按 `Ctrl+C`。后台实例使用旧目录中的 `node src/cli.js stop`；若启动时指定了 `--state-file`，停止时使用同一参数。该命令停止此注册文件中的全部实例，确认它们均可停止后再执行。
3. **停稳后备份数据。** 复制完整的 `~/.codex-usage/` 到新的备份目录。自定义位置和外置历史按下节一并保留。
4. **从新目录按原参数启动。** 两版均运行 `node src/cli.js run`；原来使用自定义 home、端口或服务注册文件时继续使用原参数。程序自动迁移既有索引，首次准备统计可能较慢。
5. **核对后继续使用。** 查看全部范围、较早月份、各来源及新增记录；Waifu 另核对价格和成就。确认稳定前保留旧程序与升级前完整备份。

默认启动命令：

```sh
node src/cli.js run --host 127.0.0.1 --port 3765
```

`~` 表示当前用户主目录。`--home-dir` 会影响默认数据和配置位置，升级时沿用原值，不要为升级临时指向空目录。不要删除用量索引或手改数据库版本来代替迁移。

## 需要保留什么

默认 `~/.codex-usage/` 中包括用量索引、来源配置、服务注册及 Waifu 价格和成就档案。停止服务后复制完整目录，并保留仍存在的 SQLite `-wal`／`-shm` 文件。

自定义用量库、配置文件和外置历史也需一起备份：

- **主用量库**：包含已经索引、可能已被上游清理的历史，不能只备份原始会话日志。
- **外置冷包及相邻 manifest**：按完整目录保留；只复制主 SQLite 会遗漏已封存历史。
- **成就档案**：默认 `achievements.sqlite`；自定义用量库的档案位于该库旁边，名称由程序生成。它不是可重建缓存。
- **压实映射与新旧包**：做过压实时保留 `compaction.json` 和映射引用的文件，直到回滚窗口结束。

历史命令可以生成可校验的用量备份或完整包，但来源配置等本地文件仍需另外保留，见[备份与转移](history-retention.md)。

## 切换 Waifu 与 Lite

先停止当前实例，再启动另一版，并使用相同数据位置。

Lite 保留已有用量、来源配置、价格文件、浏览器皮肤偏好和成就档案。Lite 期间暂停评估成就。切回 Waifu 后，原档案身份、启用时间、获得日期与已读状态继续有效，仍可核实的用量也会计入成就。分享和角色成就以档案中的实际操作记录为准。

两版看板均使用服务机器本地时区，旧 UTC 选择不再影响日期。Lite 固定深色；切回 Waifu 后继续使用其深浅主题与角色偏好。原始时间戳和成就档案的固定日历保持原值。

Lite 新历史包使用无价目的 v3，两版继续读取既有 v1／v2／v3。成就完整恢复由 Waifu 显式提供，详见[历史格式](history-retention.md#历史格式兼容)和[成就恢复](achievements.md#档案与备份)。

## 恢复与程序回滚

历史恢复使用新的目标文件或目录，不自动切换正在运行的服务。Waifu 需要恢复备份中的成就时，显式添加 `--with-achievements`；普通恢复只恢复用量。

回到旧程序时，先停新实例并完整保留升级后的数据，再使用**旧程序和升级前的完整数据副本**恢复到独立位置。旧程序不要直接打开升级后的活动库。旧副本不包含升级后新增或修订的记录，因此升级后的完整状态也需保留。

归档压实回滚使用当前主库与原 `compaction.json` 逆向切换引用，和程序回滚不同，见[归档压实](history-retention.md#归档压实与回滚)。
